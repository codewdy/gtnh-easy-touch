**0.4.76 改用游戏内输入框的 Windows UI Automation（UIA）接口，移除上方系统编辑弹窗。焦点、可编辑状态、文本和实际位置直接来自 MC 输入框；隐藏的 Win32 光标向 Sunshine 提供游戏内光标位置。输入、选区、点击、Enter/Esc 均由游戏自身处理。**

Windows 10/11 x64 默认启用 `text.nativeTextInput=true`，不需要先触发原生触摸。支持原版 `GuiTextField`、NEI 可见文本框和 ModularUI 1/2 的单行 `TextFieldWidget`。告示牌、书本、多行控件和其他自绘文本编辑器暂未接入。关闭这项配置并重启可恢复普通 MC 输入。

UIA provider 挂在现有 SDL 游戏窗口上，全屏期间保持游戏窗口和焦点，不再临时切换显示模式或修改暂停设置。接口通过标准 [Windows UIA provider](https://learn.microsoft.com/en-us/windows/win32/winauto/uiauto-serversideprovider) 实现；小型 Windows x64 DLL 从本项目 C++ 源码编译后内嵌于 jar，首次运行按 SHA-256 解包到系统临时目录缓存，不需安装外部服务。输入仍经过 lwjgl3ify/SDL 和原控件的校验；UIA ValuePattern 写入排队到游戏线程执行，过期焦点的写入会被丢弃。

已核对 Foundation Sunshine `v2026.1020.23431.杂鱼`、面板 `v0.6.5` 和 Moonlight V+ `v12.14.0`。自动弹键盘要求近期远程点击与输入框位置匹配；现在上报实际 MC 输入框位置。只用快捷键打开聊天且没有近期远程点击，仍不能保证弹出键盘。下方输入框被键盘遮住时，Moonlight 仍可能按真实光标位置上移游戏画面；这版没有关闭客户端避让。

Sunshine 该稳定版的 UIA 收键盘仍要求新的远程点击，仅按 Enter/Esc 离开输入框可能不会自动收起。这是 [Sunshine 的关联条件](https://github.com/AlkaidLab/foundation-sunshine/blob/66d27405e43ba1cc5e8c88dda88ba44f06ac56b8/src/text_context/bridge.cpp)，模组会正常上报焦点结束，但不伪造远程点击。客户端自动输入法行为见 [Moonlight V+ 实现](https://github.com/qiin2333/moonlight-vplus/blob/v12.14.0/app/src/main/java/com/limelight/utils/RemoteImeController.kt)。

## 安装与使用

1. 使用 GTNH 2.9.0 RC2 现代 Java 版（自带 lwjgl3ify 3.0.37 和 SDL3），将 `build/libs/gtnh-easy-touch-0.5.3.jar` 放入客户端的 `mods/`，并移除旧版 Easy Touch jar。不要安装 `-sources.jar` 或 `-dev.jar`。
2. 在串流软件中开启原生触点透传；模组不依赖串流软件额外模拟鼠标点击。真实鼠标或串流按键发送的左右键保持原版行为。
3. 点击右下角全局菜单显示/隐藏触屏按键、配置映射，或打开“功能配置”窗口修改自动上台阶、优化 tooltip 和自动切换工具；修改立即保存，返回按钮或 Esc 回到原界面。本模组不再向游戏控制菜单注册快捷键。

世界右半屏与普通 UI 统一单击左键、双击右键：第一次抬手后等待 250ms，在同一位置再次点击则只发右键。单次按住 250ms 为左键保持，双击第二次按住为右键保持，移动可拖动，松手释放。世界内快速滑动仅转视角，左半屏自由摇杆继续控制移动。

持原版剑、继承 ItemSword 的剑或匠魂 Broadsword、Longsword、Rapier、Cleaver、Cutlass，且准星命中生物或可攻击实体时，落指立即攻击，连续点击连续攻击，不等待或识别双击。此例外不应用于 UI。

背包物品、NEI 列表、书签与配方物品保留静止长按菜单；菜单出现前移动会进入左键拖动。轻点和双击走统一左右键逻辑；双击第二次按住可右键拖动，不弹长按菜单。菜单已经打开时，当前手势归菜单处理。

旧 Smart 匹配、开关、准星提示和双指鼠标手势均已删除；旧 matcher 配置不再读取。真实鼠标行为不变。

## 自定义触屏按键

点击游戏右下角的小菜单按钮，向上展开全局控制菜单；世界、背包、机器和其他 GUI 中都可使用：

- **隐藏/显示所有按键**：统一控制自定义触屏按键和摇杆指示器，右下角菜单按钮自身始终保留。隐藏时释放正在按住的输入；重新显示遵循各按键原有的世界/其他规则，不改写布局。开关保存在 `config/gtnheasytouch.cfg` 的 `touch.showButtons`，重启后保留。
- **配置按键映射**：进入布局编辑器。原暂停菜单入口和“编辑触屏按键布局”快捷键已移除，仍可用 `/easytouch layout` 直接打开。
- **自动切换工具：开启/关闭**：默认开启，开始挖掘及持续挖掘时从快捷栏选择工具，优先保证可以采集掉落物，其次比较游戏计算的挖掘速度；效果相同时保留当前工具。支持鼠标和触屏，不移动背包物品，不在攻击实体或创造模式下切换。停止挖掘后保留所选工具；开关保存于 `mining.autoTool`。
- **自动上台阶：开启/关闭**：默认关闭，开启后陆地和水中均最多跨 1.25 格，水中可辅助上岸，支持按住跳跃键向上游；仍需满足原版的着地或本次下落碰到地面的跨步条件。潜行时暂停。开关保存于 `config/gtnheasytouch.cfg` 的 `movement.autoStep`，重启后保留，独立于触屏按键显示开关。按移动方向和惯性检测前方碰撞面的实际高度差，动态设置本次跨步高度；上升路径或落脚空间不足时保留原有行走方式。

菜单项在手指抬起时执行；点击外部收起菜单，该次触摸不会穿透到游戏或 GUI。菜单打开时释放当前触摸操作。布局编辑器只负责布局与单个按键属性；即使全局隐藏按键，也可在编辑器中预览和修改。

- 点“新增”后打开映射，使用虚拟键盘点选一个或多个键，再点“确定”文字按钮。已选键高亮，再点一次取消；“清空”重选，“数字/导航”切换数字小键盘与导航键页。支持 Shift+T、Ctrl+R 等组合键，也支持多个普通键；选择只在确认后生效；主键盘及数字/导航页末尾的“左 / 右 / 中”对应鼠标左、右、中键，可与键盘键组合，例如 Shift+鼠标左键。清空后也可以确认保存空映射。
- 新映射保存具体键码；旧的游戏功能映射仍可使用，重新编辑并确认后转为具体键码组合。按键未绑定或已移除时显示红色 `!`。
- 触屏按钮和虚拟键盘键帽均为圆形，命中区域与圆形一致。外围有细环边框，按下/保持状态以绿色环高亮，编辑选中时为金色环；按钮文字缩至 80%。圆形填充和边框使用连续几何与约一个屏幕像素的透明过渡，不再按 GUI 像素画台阶；摇杆同步改用该渲染。文字仍使用 Minecraft 原有字体，仅将绘制起点对齐真实屏幕像素，保留像素字体风格。编辑器的工具栏、属性、子选项列表及确认/取消均为带深色背景、细边框和居中文字的矩形按钮，整个按钮区域都可点击，悬停高亮；右下角菜单向上展开四个文字选项，直接点击对应文字行选择。新触屏键默认不透明度为 30%；旧布局默认的 55% 自动迁移为 30%，其他自定义透明度保留。
- **弹出菜单**：在按键属性中点“触发”切换到“弹出菜单”，再点“配置子选项”新增、编辑或删除项目。每项可单独命名并配置单键、组合键或鼠标键。保存后轻触菜单按键，在该按键附近展开文字列表（优先向上，空间不足时调整位置）；点选子选项并抬手后按下、释放一次，随后收起菜单；长按不连发。直接点击文字行选择，菜单统一使用深色背景与细边框，按最长文字宽度加内边距自动适配（超宽时限制在屏幕内）；无独立按钮图标或全屏遮罩，点击外部取消，不向底层传递点击；多项时支持翻页，空菜单显示配置提示。子选项不使用按住/切换模式，菜单沿用父按钮的世界/其他显示设置。
- 新建按键默认大小为 24、映射为空，不再预选 Space。可修改名称、大小、不透明度和触发方式：按住触发、点击切换、弹出菜单。旧版“点按一次”自动迁移为按住触发，已有显式 Space 映射保留。切换按住时按钮高亮，再点一次释放。
- “世界”和“其他”独立控制显示：世界表示未打开 GUI 的游戏画面；其他表示背包、机器、NEI、聊天、菜单等 GUI。可同时开启，也可全部关闭以保留但隐藏按钮。
- 编辑操作统一放在屏幕顶部：布局页提供新增、编辑、删除、预览、保存和取消，窄屏自动换行；属性页顶部返回布局，虚拟键盘顶部切换键盘、清空、确定和取消。
- 在布局画面点击选中并拖动位置，“编辑”修改属性，“删除”移除按钮。直接点击画面中的按钮进行选择；自由摇杆无需固定位置布局。
- “预览”切换世界/其他布局；同一按钮在两种模式共用位置，需要不同位置时可分别新增两个按钮。按键重叠时最后新增的按钮优先。
- 点“保存”立即生效，写入 `config/gtnheasytouch-layout.json`；“取消”或布局页 Esc 放弃草稿。旧布局的 Smart 副键迁移为普通“使用”按钮，新布局不自动添加。

触屏按钮优先接收触点，按住后手指滑出仍归原按钮处理，松手释放，支持与摇杆和视角同时操作；按钮不向底层 GUI 发送鼠标点击。切换界面、失焦、死亡、隐藏世界 HUD 或触点重置会清理按键状态，切换按住也会重置。

GUI 通过 lwjgl3ify 键盘事件队列接收组合键：先按下修饰键、再按普通键，释放时反向处理。虚拟按键状态与实体键盘状态合并，供 GUI 的 Shift/Ctrl 判断使用；多个触屏按钮共享修饰键时，最后一个按钮松开才释放。按住触发、点击切换均支持组合键；切换界面、失焦和触点重置会清理整个组合。尚未提供宏、输入法或自动连发。GUI 的 R/U 等悬停快捷键使用当前鼠标指向的物品，先触摸定位物品，再点自定义按键。

## Tooltip 优化

全局菜单提供“优化tooltip”，默认开启，开关保存在 `config/gtnheasytouch.cfg` 的 `touch.optimizeTooltip`，切换后即时生效。关闭时停止提示接管和触摸滚动，并恢复 NEI 右侧栏的原始布局；原生提示的显示条件与绘制逻辑继续由游戏和模组控制。

开启时，NEI 右侧物品栏固定使用原区域上半区，列表网格、分页、右侧搜索/数量控件和历史/可合成子栏同步调整，下半区专供 tooltip。提示在这块右栏下半区域内左上对齐，最大宽度为原栏宽、最大高度为原栏高的一半；左侧书签栏保持原尺寸。窗口过小时保留可用的原生布局。无需长按显示提示。普通文字按右栏可用宽度自动换行，宽度计算包含边距并适配 tooltip 缩放，主要使用上下触摸滚动；图标、表格或其他无法缩窄的原生组件保留横向滚动，触摸不穿透。长按操作菜单仍在触点附近弹出，与提示独立。

当前 GTNH 整合包通过 Chromatic Tooltips Compat 接入 AE 的物品、虚拟槽与按钮文字提示，以及 ModularUI 1/2 的物品、文字和富文本提示，继续调用其原生组件绘制器。非物品提示重新生成上下文时保留滚动位置。没有可用 NEI 右栏区域的界面，或绕过上述绘制链的其他自绘提示，保留原生位置。

提示的背景、边框、颜色、图标、字体和组件继续由原模组绘制，滚动视口不额外铺设纯色底板。Chromatic 使用原生完整内容布局代替分页以支持滚动，保留主题、动画、缓存和绘制事件；NEI 特殊提示行仅在当前帧测量并绘制，不跨帧保存临时富文本索引。

## 多点触控转发与检测

使用 GTNH 现代 Java 版的 lwjgl3ify 3.x，在进入世界后执行客户端命令 **`/easytouch touch`**。命令不需要 OP，也不发送给服务器。打开页面后，用手指按住并移动：

- 监听状态应为“已连接”；`DOWN / MOVE / UP / CANCEL` 显示 SDL 是否启用了相应事件。
- 绿色十字和手指编号表示 SDL 原生触点。当前触点数达到 2，且两个标记能独立移动，表示当前输入链路确实送来了独立的多指数据。抬起后当前数量应减少。
- 灰色 `[MOUSE]` 标记表示 SDL 从鼠标模拟的触点，不计入原生触点数量或峰值。
- “鼠标事件”在变化而原生触点始终为 0 时，先检查上方 SDL 事件开关，再检查串流软件的触点透传；单凭这个现象不能断定 UU 的所有模式都不支持。
- “重置触点统计”清除触点事件计数、最后事件及历史峰值，仍按住的触点继续显示；鼠标和队列丢弃数统计整个监听会话。按 Esc 或“完成”退出。

世界右半屏由第一根原生触点控制手势，额外触点不抢占；左半屏摇杆和独立映射按钮可以同时操作。点击规则见“安装与使用”：双击窗口 250ms，静止保持阈值 250ms，位移阈值为屏幕短边的 1.5%（至少 6 像素）。快速滑动仅转视角，已进入按住状态后移动仍保持鼠标键。普通 UI 轻点延迟发左键，双击发右键，拖动发送对应鼠标按钮；物品长按菜单另按上文规则处理。

切换界面、失焦、死亡、退出世界或触点重置会取消当前手势，恢复后需重新按下。SDL 自动生成的触摸鼠标事件统一过滤，避免重复点击或双倍转向；鼠标模拟的触点不参与手势，真实鼠标不交换左右键。`touch.enabled=false` 关闭触摸接管和过滤，恢复 SDL 原有输入。

触摸拖拽灵敏度在已有配置文件 `config/gtnheasytouch.cfg` 的 `touch` 分类中设置，启动新版后会自动补上默认项，不需要删除旧配置。退出游戏后编辑，重启生效：

```text
touch {
    D:dragSensitivity=1.0
}
```

范围为 `0.1`～`5.0`：`1.0` 保持当前速度，`0.5` 为半速，`2.0` 为两倍速度。它在游戏鼠标灵敏度基础上乘以该倍率，仅影响世界内触摸拖拽；真实鼠标、GUI 触摸定位、点击/长按时间和拖拽判定阈值不受影响。越界值限制到范围内，无效数字恢复为 `1.0`。

`config/gtnheasytouch.cfg` 的 `touch` 分类：`B:enabled=true` 默认启用触摸接管，`B:logEvents=false` 默认不逐条记录。关闭转发仍要求 lwjgl3ify 和 SDL3 可用。需要排查时可退出游戏，把 `logEvents` 改为 `true` 后重启；日志中的 `[Touch]` 会记录按下、抬起、取消和状态清理，移动事件不刷日志。运行中的回调异常会记录错误、释放触点状态并停用转发，避免 Java 异常跨越原生回调边界。

接入使用 SDL3 的 [`SDL_AddEventWatch`](https://wiki.libsdl.org/SDL3/SDL_AddEventWatch) 复制原生触点，并使用 [`SDL_SetEventFilter`](https://wiki.libsdl.org/SDL3/SDL_SetEventFilter) 过滤当前窗口中来源为 `SDL_TOUCH_MOUSEID` 的模拟鼠标事件；保留原有事件过滤器调用链。SDL 内部按下/松开状态继续更新，不在 GUI 切换时反复开关模拟功能。客户端 tick 开始时先转发触点，再执行手势判定；GUI 鼠标事件直接进入 lwjgl3ify 的鼠标队列，不回送 SDL。物理按钮单独记录，防止过滤掉的模拟左键通过底层状态恢复成按住。没有修改 lwjgl3ify 的字节码或磁盘 jar，也没有另起事件轮询。

原生回调可能来自其他线程，因此先复制数据进入有界队列，再于 MC 客户端 tick 发布 `MinecraftForge.EVENT_BUS` 上的 [TouchInputEvent](src/main/java/io/github/wdy/easytouch/touch/TouchInputEvent.java)。该事件不可取消，只转发数据；坐标原点在窗口左上角，通常范围为 0..1，允许边界外坐标。失焦、切换世界、队列溢出或接口错误时发布 `RESET`，消费者应清除全部按住状态。模拟鼠标触点通过 `sample.simulated()` 区分。触控代码直接使用 `SDL_Event`、`SDL_TouchFingerEvent`、`SDL_EventFilter` 和 `Display.sdlWindowId`；lwjgl3ify、LWJGL3 的 Java 绑定作为 `compileOnly` 依赖，运行时由整合包提供，不把依赖或原生库打入 mod。

`TouchInput` 和 `SdlTouchSource` 使用 `@Lwjgl3Aware`，防止 lwjgl3ify 的 [LWJGL2 重定向器](https://github.com/GTNewHorizons/lwjgl3ify/blob/3.0.37/src/main/java/me/eigenraven/lwjgl3ify/rfb/transformers/LwjglRedirectTransformer.java) 将 `org.lwjgl.sdl.*` 改写为不存在的 `org.lwjglx.sdl.*`。带此标记的 `TouchInput` 显式使用 `org.lwjglx.input.Mouse` 和 `org.lwjglx.opengl.Display`；其他类仍保留正常的 LWJGL2 兼容重写。如果旧版出现上述缺类错误，替换 Easy Touch jar 即可修复这处包名错误，无需额外安装 SDL jar。

## 配方树合成按钮

独立的“打开 NEI 合成树（等效 Shift+T）”快捷键已移除，继续使用 NEI 自带的 Shift+T。

悬停书签、右侧 NEI 物品列表、中间配方的产物/材料或背包槽位中的物品，按 **Shift+T**，即可使用该物品的收藏配方直接打开临时配方树，不向书签页添加合成组。优先使用爱心手动收藏的配方，其次使用 NEI 自动收藏的配方；只有物品收藏标记、没有配方或原配方已失效时不新增合成组。匹配遵循 NEI 自己的物品、元数据、NBT 和流体规则。

临时树打开时，目标设为原容器可取用槽位中的已有成品数量 + 1；没有库存时为 1。例如每批产出 4 个、已有 10 个时，目标为 11。目标数不再要求为配方产量的倍数。仅在新建临时树时初始化一次，目标范围为 1 到 2147483647。

通过物品快捷键或触摸菜单创建合成树时，会将最初选择的配方固定为目标产物；例如“燧石 → 燧石臼 → 燧石”的循环依赖不会再把目标反转成燧石臼。目标保留在临时树中，数量调整与实际合成使用同一目标。循环中的起始材料仍需自行提供。

此操作复用 NEI 的收藏配方展开逻辑：按收藏递归展开原料、遵循展开深度与候选材料设置，再用独立的内存合成组打开原生配方树。每次打开创建新的临时树，不添加、覆盖或保存书签，也不会直接执行合成。快捷键沿用 NEI 的“打开合成树”绑定（默认 T，加 Shift）；搜索框输入优先，长按重复事件不创建新树。原生爱心按钮上的 Shift+T 同样打开临时树；收藏点击、Shift+A 保存配方及已有书签组的打开操作保持原有行为。

临时树提供“合成”和“尝试合成”两个操作按钮，退出使用原生返回操作，不提供分享书签组功能。合成保留完整配方链和容器同步等待；返回容器时不提前清除待执行的计算数据。临时数据不写入书签文件。

配方树左侧提供单列数量按钮，从上到下固定为 `+64 / +1 / -1 / -64`，直接加减目标物品数，最小为 1；流体显示使用 L 单位。按下立即调整一次，按住 0.4 秒后每 0.1 秒重复；松手、移出、关闭界面、调整窗口大小或失焦停止。主键和副键触控均可使用，多目标时点击顶部图标切换。精确目标仅在当前会话内保存，原生书签保留对应完整批次数；重新启动游戏后不保留非整批目标。

根节点上方显示 `已有 x + 待补 y`，其中 `y = max(目标量 - 已有量, 0)`；悬停提示显示精确目标。库存约每 250ms 刷新。原生图标和材料统计仍按完整批次展示；执行按精确目标与同步库存的差额计算。例如已有 3、目标 10、每批 4 个，执行两批，最终 11 个；已有数量达到精确目标时无需继续合成。

鼠标悬停在配方树目标产物上，滚轮按物品数增减 1；Alt + 滚轮保留 NEI 的步长设置，但同样以物品数为单位。调整后刷新树和合成按钮状态。

Ctrl + 滚轮仍由 NEI 原生处理；Shift + 滚轮保留原有的候选材料切换或横向滚动。非目标节点、画布空白处和统计面板维持原操作；开启 NEI 的 `Tree Zoom without Ctrl` 后，目标产物上的直接滚轮优先调整数量，移到空白处仍可缩放。此功能仅针对配方树，不改变外部书签面板。

配方树左上角 Save Image 后显示工作台图标的“合成”按钮和蓝色播放图标的“尝试合成”按钮，临时树和已有书签组的树使用相同操作。需要开启 NEI 自动合成，并从工作台或支持自动合成的容器打开；悬停显示操作说明，无法合成时变灰。

“尝试合成”跳过按钮和容器同步后的可合成性预检，直接让 NEI 尝试当前计划，适合验证有启动材料的循环配方；不保证循环一定完成。仍需开启自动合成、有效合成链及原容器，鼠标不能持物，且不能已有合成任务。窄窗口下该按钮排列在“合成”按钮下方。

点击后返回原容器，等待输入松开和服务端背包同步，再执行当前树的合成计划；不添加或删除书签。临时树和已调整数量的目标按精确数量补齐，实际配方执行次数向上取整；未调整的原生书签目标仍沿用 NEI 原有补齐规则。退出使用 NEI 原生返回操作。

鼠标或触屏点击按钮，松开后开始处理。本模组不再注册配方树合成快捷键，NEI 自带快捷键仍由 NEI 处理。

返回容器后会先等待服务端同步槽位和鼠标持有的物品，再启动合成。等待期间手动点击容器、按键、关闭界面或失焦会取消本次启动；同步超时会提示重试。鼠标上已有物品时，请先放回背包再点击“合成”。

自动合成仍受 NEI 原有的材料、配方和容器支持范围限制；这两个按钮不负责启动 GT 机器加工或提交 AE2 网络合成任务。未开启自动合成、没有有效合成组或原容器、光标持有物品、等待同步或正在合成时，两个按钮都会置灰，悬停显示原因。“合成”另外检查是否至少有一步可执行，每 250ms 刷新预检结果，并在点击时及容器同步后重新检查；“尝试合成”跳过这项预检。两者均不保证整条链能够一次完成。

接口按 [GTNH 2.9.0 RC2 官方清单](https://github.com/GTNewHorizons/DreamAssemblerXXL/blob/master/releases/manifests/2.9.0-RC-2.json) 中的版本编译。NEI 是可选依赖，无需另外安装其他辅助模组；接口不兼容时记录日志并停用这项功能。

| [TouchMouse.java](src/main/java/io/github/wdy/easytouch/input/TouchMouse.java) | GUI 内触摸模拟鼠标点击与拖动 |
| [TouchActions.java](src/main/java/io/github/wdy/easytouch/input/TouchActions.java) | 将左键/右键状态提交给攻击/使用绑定 |
| [KeyStateMerger.java](src/main/java/io/github/wdy/easytouch/input/KeyStateMerger.java) | 攻击/使用按键的状态合并、一次点击和队列清理 |
| [MinecraftInput.java](src/main/java/io/github/wdy/easytouch/input/MinecraftInput.java) | Minecraft 环境判断和底层按键读写 |

[touch/](src/main/java/io/github/wdy/easytouch/touch/) 包含独立的原始触点管线：`SdlTouchSource` 管理 SDL 回调及原始字段复制，`TouchQueue` 负责跨线程传递与状态清理，`TouchTracker` 维护多指状态，`TouchInput` 在客户端线程发布事件并注册检测入口，`TouchDebugScreen` 显示检测结果。`SdlTouchMouseFilter` 过滤自动生成的模拟鼠标事件并记录物理按钮，`GuiTouchMouse` 注入 GUI 鼠标事件；世界内触摸动作由 `ClientInput` 接入按键合并层。

触摸动作通过 `Source` 提交攻击和使用按键的映射与点击请求，由底层统一写入 Minecraft。结束接管时恢复当前物理按键状态，进入 GUI 或切换模式时由入口清理正在进行的输入和待执行点击。

[NeiCraftingTreeInput](src/main/java/io/github/wdy/easytouch/nei/NeiCraftingTreeInput.java) 仅在客户端加载 NEI 时注册，负责配方树按钮、滚轮事件、可合成状态检查和返回原容器启动 NEI 自动合成。[NeiTreeQuantityScroll](src/main/java/io/github/wdy/easytouch/nei/NeiTreeQuantityScroll.java) 复用原生画布命中、数量规则和刷新方法，使用实时鼠标坐标适配 GUI 缩放及画布缩放、平移，不模拟 Ctrl 按键。

[NeiFavoriteTreeShortcut](src/main/java/io/github/wdy/easytouch/nei/NeiFavoriteTreeShortcut.java) 在 NEI 的末阶段按键回调中读取悬停物品及收藏配方，调用原生 `GuiFavoriteButton.saveRecipeInBookmark()` 并打开新组。无需注册额外按键，也不复制 NEI 的递归配方算法。

## 触摸板

点击右下角触摸板图标开启或关闭。单指快速滑动移动光标；单击等待 250ms 后发左键，250ms 内同位置再次点击只发右键。静止按住 250ms 后进入左键拖动；双击时第二次按住 250ms 后进入右键拖动，松手释放。额外手指不触发右键、滚动或接管当前手势。

切换 GUI、失焦、重置触点会取消待执行点击并释放按键；返回世界时退出触摸板。保留多触点输入管线，供摇杆、视角与独立映射按钮同时使用，不再提供双指组合手势。

## 构建

使用 Java 25 和 MinGW-w64 的 x86_64 C++ 编译器执行 `./gradlew build`（Windows：`gradlew.bat build`）。默认调用 `x86_64-w64-mingw32-g++`，可通过环境变量 `MINGW_CXX` 指定编译器完整路径；需要 MinGW-w64 的 UIAutomation 头文件。`buildWindowsUia` 自动编译并打包 DLL，`sourcesJar` 包含对应 C++ 源码。Gradle 自动获取编译所需的 Java 8；产物使用 Java 8 字节码，但运行环境仍需满足 lwjgl3ify 和 SDL3 的要求，请使用 GTNH 现代 Java 版。

项目不保留常驻测试代码、测试依赖或 SDL 专用测试任务。允许按需进行针对性测试，测试代码和脚本使用临时目录（如 `/tmp`），不归档到项目测试目录，避免积累大量回归测试。正常构建负责编译与打包，游戏操作效果按需在客户端确认。

拆分数量滑条支持触摸拖动、鼠标拖动和滚轮微调；点击确认才执行，取消或点击外侧关闭。AE2 `rv3-beta-1080-GTNH` 网络物品列表支持同一长按菜单，按物品身份调用原生单个取物协议，每次等待鼠标持有数量更新后继续。列表重排不会改变目标；库存不足、网络断电或同步超过 3 秒则停止并提示已持有数量。再次点击、按键、滚轮、切换界面或失焦会停止后续请求；已发送的一次请求仍可能完成。此功能不提交自动合成任务，Easy Touch 仍只需安装在客户端。

### JourneyMap 图标大小

`config/gtnheasytouch.cfg` 的 `map.journeyMapIconScale` 控制 JourneyMap 5.2 的独立图标倍率，默认 `2.0`，范围 `1.0–8.0`。设为 `1.0` 恢复原尺寸；退出游戏修改，重启生效。不跟随 GUI 缩放，不改写 JourneyMap 配置。覆盖大小地图的自身标志、实体和路标，并同步路标命中尺寸；原有实体倍率和小图标选项仍然生效。此适配针对实例中的 5.2.23 验证，不保证其他版本兼容。

0.5.3 将同一倍率扩展到 VisualProspecting 1.5.41 的矿脉图标及名称、地下流体名称与产量，以及 TCNodeTracker 1.4.6 的灵气节点图标。矿脉和节点命中区域同步放大；地下流体区块覆盖范围不变。仅在 JourneyMap 绘制路径生效。

0.5.3：小地图窗口宽高也跟随 `map.journeyMapIconScale`，单边最多为屏幕短边的 80%，图标倍率不重复应用。JourneyMap 大地图支持原生双指捏合缩放，每约 25% 距离变化切换一个原生档位；多指期间取消单指鼠标手势，全部抬起后恢复。
